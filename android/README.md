# Vida Cotidiana — Android (AND-001/AND-002/AND-003)

Stack (08-android-architecture.md): Kotlin, Jetpack Compose, Hilt, Coroutines/Flow,
Navigation Compose, Retrofit/OkHttp, Kotlin Serialization. `minSdk = 30` (DEC-011).

**ASSUMPTION:** exact AGP/Kotlin/Compose BOM/Hilt versions (AGP 8.5.2, Kotlin 2.0.20,
Compose BOM 2024.09.00, Hilt 2.51.1, Gradle 8.9) are a technical bootstrap choice, not
an approved business decision — resolves the "versiones exactas TBD al crear el
proyecto" note in `17-dependencies.md`.

## AND-002 — login (real, verified on a physical device 2026-08-16)

AppAuth-Android (`net.openid:appauth`), Authorization Code + PKCE (S256, generated by
AppAuth itself) against the `android-app` Keycloak client (Phase 1, public client, no
client secret). Login opens Custom Tabs, never a WebView (AppAuth's own security
guidance). Tokens are stored in `EncryptedSharedPreferences`
(`core/security/TokenStore.kt`, AES256-GCM, key material in the Android Keystore).

Redirect: `com.vidacotidiana.app://callback`, wired via
`manifestPlaceholders["appAuthRedirectScheme"]` in `app/build.gradle.kts` — verified in
the built APK's actual merged manifest (`aapt dump xmltree`) and, since, by a real login
completing on a physical device.

## AND-003 — reminders (real, verified on a physical device 2026-08-16)

Retrofit + OkHttp + kotlinx.serialization (`com.jakewharton.retrofit:retrofit2-kotlinx-serialization-converter`),
an OkHttp interceptor attaches `Authorization: Bearer <token>` from `TokenStore`.
`RemindersScreen`/`RemindersViewModel`: list (`GET /reminders`), create
(`POST /reminders`), complete (`POST /reminders/{id}/complete`).

Token refresh-on-401 is **not implemented** in this bootstrap (ASSUMPTION, not a
decision — ties into token-lifecycle hardening, out of scope for this first vertical
slice; the access token is short-lived, 5 min, same as every other client in the realm).

### Four real bugs found and fixed getting this to pass

Screenshots (`UiDevice.takeScreenshot`) turned out unreliable — they write in-process,
so they land in the app's own external-files-dir, which AGP wipes when it uninstalls
the app right after `connectedAndroidTest` finishes, before there's any chance to `adb
pull` them. On any failure the test dumps the semantics tree to Logcat instead
(`composeRule.onRoot().printToLog(...)`, tag `VC_TEST_<step>` — `adb logcat -d | grep
VC_TEST`), which has no such file-lifecycle problem. That's how each of these was
actually diagnosed, not guessed:

1. **AppAuth's `RedirectUriReceiverActivity` requires a `Theme.AppCompat` theme.** The
   app's plain platform theme (`@android:style/Theme.Material.Light.NoActionBar`)
   crashed it on the redirect back from Keycloak with `IllegalStateException: You need
   to use a Theme.AppCompat theme`. Fixed: `res/values/themes.xml` defines
   `Theme.VidaCotidiana` extending `Theme.AppCompat.Light.NoActionBar`; the manifest
   references it.
2. **AppAuth's `DefaultConnectionBuilder` refuses non-HTTPS connections outright** —
   `IllegalArgumentException: only https connections are permitted` — which blocked the
   token exchange against the local dev Keycloak (plain HTTP by design; no TLS cert for
   a LAN IP/`10.0.2.2`). Fixed with a debug-only carve-out, mirroring the Network
   Security Config pattern already used for cleartext traffic:
   `core/network/DebugConnectionBuilder.kt` (in `src/debug`) plus
   `core/network/AppAuthConfigProvider.kt`, provided per variant — `src/debug` allows
   plain HTTP, `src/release` keeps AppAuth's own HTTPS-only default untouched.
   `AuthManager` constructs its `AuthorizationService` with
   `AppAuthConfigProvider.config`.
3. **`MainActivity` got recreated when Custom Tabs handed control back**, orphaning the
   `ComposeTestRule` bound to the original instance — clicks and text input kept
   "succeeding" against a UI no longer driving any live `ViewModel` (symptom: no new
   reminder ever appeared, nothing reached the backend, yet no error was thrown either).
   Fixed: `android:launchMode="singleTask"` on `MainActivity` in the manifest, so
   Android reuses the existing instance for that redirect instead of creating a new one.
4. **The reminders list keeps every reminder ever created against the real backend**
   (no reset between test runs), so an ambiguous "Complete" button selector (matched by
   a loose sibling-text search) found 4 candidates across old runs' leftover reminders
   instead of exactly 1. Fixed: each `ReminderRow` carries
   `Modifier.testTag("reminder_row_${reminder.title}")`, and the test targets the
   "Complete" button by `hasAnyAncestor(hasTestTag(...))` scoped to that specific row.

Also worth knowing, not a bug in the app: on this device (Spanish locale, Samsung
predictive keyboard), `performTextInput` — which goes through the real IME — got
autocorrected into `"nuevareminder"` instead of the intended text.
`performTextReplacement` sets the field's value directly via the `SetText` semantics
action, bypassing the keyboard entirely; that's what the test uses.

### Running it yourself

```
adb devices -l                                    # confirm `device`, not empty/unauthorized
adb install -r app/build/outputs/apk/debug/app-debug.apk
./gradlew connectedDebugAndroidTest
```

Requires the `testuser`/`TestPass123!` account created in the Keycloak dev realm during
Phase 1, and the backend/Keycloak reachable from the device — see host resolution below.
**The Mac's LAN IP changed mid-session via DHCP renewal** (`192.168.0.18` →
`192.168.0.31`) — if the test can't reach Keycloak/the backend, check the Mac's current
IP (`ipconfig getifaddr en0`) first before assuming anything else is broken.

### Connecting a device (troubleshooting)

```
adb devices -l
```

- **Empty list:** the phone isn't plugged in, or **"USB debugging" isn't enabled** —
  this is a separate switch from "Developer options" itself, under
  Settings → Developer options → USB debugging. Enabling "Developer options" alone
  (tapping Build number 7 times) is not enough.
- **`unauthorized`:** a popup titled "Allow USB debugging?" is waiting on the phone's
  own screen — tap Allow there, then re-run `adb devices -l`.
- **`device`:** ready — proceed with the install/test commands above.

### Backend/Keycloak host resolution

- **Emulator:** `10.0.2.2` (special alias to the host's `localhost`) — the checked-in
  default in `app/build.gradle.kts` (`OIDC_ISSUER`, `API_BASE_URL`) and in
  `app/src/debug/res/xml/network_security_config_debug.xml`.
- **Physical device on the same LAN (verified real):** replace `10.0.2.2` with the
  Mac's current LAN IP in those two `buildConfigField` values, add that same IP to
  `network_security_config_debug.xml` (cleartext HTTP is only allowed for the domains
  listed there, debug builds only — never in release), **and** restart the backend with
  `OIDC_ISSUER` pointed at that same IP (Keycloak's dev-mode issuer is resolved from the
  request's Host header, so a token obtained by hitting the LAN IP carries
  `iss: http://<LAN IP>:8081/...` — the backend must validate against that same issuer,
  not just `localhost`).

## Structure

```
app/src/main/java/com/vidacotidiana/app/
  core/network/    — Retrofit API, DTOs, Hilt network module (AND-003)
  core/security/   — EncryptedSharedPreferences token store (AND-002)
  core/ui/         — empty, reserved
  feature/auth/    — AppAuth login screen + manager (AND-002)
  feature/reminders/ — reminders list/create/complete (AND-003)
  feature/{home,sharing,settings}/ — empty, reserved
  navigation/      — NavGraph (login → reminders)
app/src/debug/java/com/vidacotidiana/app/core/network/ — debug-only AppAuth HTTP carve-out
app/src/release/java/com/vidacotidiana/app/core/network/ — release counterpart (HTTPS-only)
app/src/androidTest/java/com/vidacotidiana/app/ — LoginAndRemindersFlowTest, HiltTestRunner
```
